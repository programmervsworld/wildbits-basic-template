# Wildbits F256K2 Starter Template

This repository provides the template that **`wildling.cli`** uses to create a new Wildbits F256K2 BASIC project. A fresh clone may run as-is, but the intended starting point for a new user is the project generated by `wildling.cli`.

## Intended workflow

`wildling.cli`, maintained in a separate repository, clones this template, customizes it for the new project, and sets it up for the user. You then work in that generated project, editing the BASIC source and adding your own assets.

The template's build scripts are designed around that setup process. In particular, the project name in `build.sh` controls the generated BASIC filename and sprite binary name. The default name, `mybasicgame`, is a starting value for the CLI to replace.

## How customization works

The BASIC source supports `#define` macros so project-specific values can be substituted during the build. `build.sh` updates the `PROJECT_NAME` and `SPRITE_FILE` definitions in `src/game.bas`, then `scripts/number.py` expands the macros and adds BASIC line numbers.

This keeps filenames referenced by the BASIC program consistent with the files produced by the build. The scripts are therefore part of the CLI's project setup workflow, rather than a generic build system.

## Using a direct clone

You can experiment with this repository directly, but you may need to perform the setup that `wildling.cli` normally handles. Review the project name in `build.sh`, the definitions in `src/game.bas`, and the device settings in `foenixmgr.ini` before building.

`build.sh` builds the BASIC program and sprite data, then transfers them to the connected device. It expects the required tools and hardware connection to be available; cloning the repository alone does not complete that setup.

## Build Script

The build script for this project has a few options that help with cross-development.

### Build Only
If you provide no options:

```bash
./build.sh
```
You will simply process all directories, move and zip up the final source in the build dir. You can then transport that zip however you'd like to deploy it manually.

### Deploy All

```bash
./build.sh --deploy
```

Will deploy all assets and code to the connected F256K2 upon completion. It will prompt you to press a key after each one individually just to prevent issues with using the serial connection.

### Deploy Code Only
```bash
./build.sh --code-only
```
Will deploy just the basic file to the connected F256K2. This prevents you from having to send the sprites and graphics every time.
